ETAT DE LA COMPILATION ET DU DEMARRAGE DU NOYAU (TPC + DEVENV /KERNELTEST)
==========================================================================

Resume
------
* TPC compile MSDOS.PAS en un IO.SYS de ~50 Ko (MAKER.PAS l'ecrit comme prevu :
  BEGIN_KERNEL a l'offset 0). Une unite qui declare "Procedure BEGIN_KERNEL" est
  compilee dans son propre segment : donnees (chaines, constantes) et routines du
  runtime SYSTEM utilisees sont recopiees dans le segment (DS=CS), l'edition de
  liens intelligente retire les routines inutilisees.
* DEVENV /KERNELTEST (headless) charge IO.SYS en 0070:0000. Le noyau :
  - initialise memoire (arene MCB apres le noyau) et vecteurs,
  - lit le disque par INT 13h, trouve C:\COMMAND.EXE (FAT12), le charge
    (relocalisations, PSP, environnement) et lui donne la main (INT 21h/4Bh),
  - COMMAND.EXE affiche sa banniere et son invite "C:\>" et recoit la frappe
    clavier (INT 21h/3Fh sur la console) ; la fin de programme (4Ch) revient au noyau.
* Script de reproduction : KERNEL/BOOTTEST.sh. Mode de mise au point : compiler
  avec -DKDEBUG (DbgW affiche des valeurs a l'ecran via INT 10h).

Ce qui est valide dans l'emulateur (BOOTTEST.sh, script "type ...")
------------------------------------------------------------------
COMMAND.EXE (compile par TPC) tourne sur le noyau et execute : VER, ECHO, DIR (repertoire courant et
sous-repertoires, totaux, espace libre reel), TYPE, COPY (lecture ET ecriture persistantes, fichiers de
plusieurs clusters, fichiers de COMMAND vers sous-repertoire), REN, DEL, MD, RD, CD (repertoire courant memorise,
".." et chemins relatifs), DATE/TIME (lecture de l'horloge BIOS). La saisie clavier est editee.

Couche FAT en ecriture (Fx*, dans MSDOS.PAS) : FAT12/FAT16 (entree FAT12 a cheval sur deux secteurs geree),
volume compact (TFxVol) au lieu du secteur de boot de 512 octets passe par valeur, entrees de repertoire
manipulees dans le tampon du secteur. Fonctions : 39h MD, 3Ah RD, 3Bh CD, 3Ch creer/tronquer, 3Dh ouvrir,
3Eh fermer (met a jour taille et premier cluster), 40h ecrire, 41h supprimer, 47h repertoire courant,
4Eh/4Fh recherche, 56h renommer, 5Bh creer (echec si existe), 36h espace libre. L'emplacement de l'entree
de repertoire de chaque handle est memorise dans Data.DataMOS (FxBase = 2486, 20 x 5 octets).
Verifie avec un lecteur FAT12 externe (KERNEL/../fatls.py n'est pas fourni : comparer l'image du disque).

Ce qui ne marche pas encore
---------------------------
* Redirection ">" de COMMAND (ECHO ... > fichier cree le fichier mais ecrit a l'ecran) : il faut 45h (DUP) et
  46h (FORCEDUP) et une table de handles par processus (JFT) ; les handles 0-4 sont codes en dur (console).
* Date/heure des fichiers crees : fixees au 1980-01-01 00:00 (INT 1Ah de l'emulateur sans horloge temps reel).
* Les autres passerelles INT 21h (FCB 0F-17/21-24/27-29, 43h, 45h, 46h, 57h, 5Ah...) ont encore les defauts
  d'ordre de parametres / DS / ADD SP : meme methode de correction que pour 3A-4F (voir @3Dh..@4Fh, @36h,
  @39h, @56h dans MSDOS.PAS).
* Le noyau s'execute sur la pile du programme appelant (COMMAND.EXE : {$M 8192}) ; MatchFileName recursif et les
  chaines de 256 octets passees par valeur consomment ~6 Ko (pile privee du noyau a prevoir).
* IO.SYS fait 50 174 octets (65 285 avant les optimisations de TPC, voir DEV-COOLS/DOC/TPC_OPTIMISATIONS.txt) :
  il reste ~14 Ko de marge dans le segment de 64 Ko.

Corrections de TPC (resume)
---------------------------
interrupt, assembler sans cadre, ABI TP7 (pas de lien statique), @Proc/Ofs/Seg,
assembleur integre etendu, references en avant, edition de liens intelligente,
segment noyau avec recopie du runtime, donnees en ligne, appel du hook Crt, etc.

Corrections du noyau (resume)
-----------------------------
DS restaure apres les blocs ASM "LDS SI,..." (SetFindState : DS restait ecrase, le noyau lisait ses donnees dans
le segment de pile de l'appelant), ordre POP ES/POP DS (TranslateBPBtoDPB),
EXEC reel + terminaison, gestionnaire de memoire (decoupe/fusion), disque INT 13h,
recherche de fichiers, handles 0-based, CurrentDir 67 octets, dispatcher INT 21h
qui conserve BX, propagation de CF dans les FLAGS, STI, PSP (DOSCall en 50h),
console par INT 10h/16h, Intr1Ah (AH ecrase), TYPE/OFFSET invalides.

Prochaines etapes
-----------------
1. Lancer BOOTTEST.sh avec un script "type ver" et suivre les INT 21h manquants
   (/KTINT:21 affiche chaque appel et son resultat) ; corriger fonction par fonction.
2. Remettre les fonctions 4Bh enfants (COMMAND lance des programmes), 4Dh, 2Ah/2Ch...
3. Valider FCB et ecriture FAT12/FAT16, puis alleger encore le segment (marge).
